# tcgen — техкарта по ручному эскизу

## Вход (от пользователя)

Только два параметра:
- **название изделия** (например, `сноуборд`);
- **размер** (например, `145`).

Если что-то не указано — спроси. Больше ничего не спрашивай без крайней нужды.

## Пути и именование (шаблон: «название изделия»+«размер»)

- Ручной рисунок: `sketches/<название> <размер>.png|jpg|jpeg` (пример: `sketches/сноуборд 145.png`).
- Техкарта: `tech_maps/<название> <размер>.md`.
- Чертёж (сгенерированное изображение): `tech_maps/<название> <размер>.png`.

Если рисунок не найден — перечисли содержимое `sketches/` и попроси положить файл по шаблону.

## Шаг 1. Прочти рисунок

Прочитай файл рисунка инструментом Read. Определи:
- состав деталей (панели, стенки, карманы, ручки, стропы, молнии, фурнитура);
- подписанные размеры и аннотации.

## Шаг 2. Составь содержание техкарты

Правила:
- **Расположение деталей сохраняй как на рисунке** — меняй только пропорции под реальные размеры изделия.
- Все размеры деталей кроя — **с припусками 1 см на каждую швейную сторону**.
- **Никакой служебной информации**: без даты составления, имени специалиста, номеров ревизий, подписей и т.п. Только то, что нужно для производства и расчёта себестоимости материалов.
- Ширина рулона ткани — из `.env` переменная `FABRIC_WIDTH` (по умолчанию 1,5 м); для тканей указывай расход в м², в комментарии — в пог. метрах.
- Названия материалов — словарём прайса: «ткань 600D», «ткань 200Д», «стропа 25мм», «стропа 40мм», «фастексы 25 мм», «полукольца 40 мм», «молния T7», «замки T7», «пряжка 2х щелевая 25 мм», «нитки». Если позиции нет в словаре — оставь как есть, калькулятор отнесёт её в «Не учтено».

## Шаг 3. Сохрани техкарту (markdown)

Структура файла — строго:

```markdown
# ТЕХКАРТА: <название изделия>, размер <размер>

## Спецификация
<2–4 строки: конструкция, внешний размер изделия Д×Ш×В>

## Детали кроя
| Деталь | Размер, см | Кол-во |
...расположение и состав — как на рисунке, размеры с припусками...

## Материалы
| Материал | Расход на изделие | Ед. изм. | Комментарий |
...
```

Таблица «Материалы» обязательна именно в таком виде — её парсит калькулятор
себестоимости (`tkcost`). Других таблиц и разделов не добавляй.

## Шаг 4. Сгенерируй чертёж через ProxyAPI (gpt-image-2)

По рисунку сделай чистый чертёж в масштабе (расположение деталей — как у пользователя):

```bash
curl -s https://api.proxyapi.ru/openai/v1/images/generations \
  -H "Authorization: Bearer $PROXYAPI_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "technical flat sketch of a <описание изделия> sewing pattern, black line drawing on white background, dimension labels in centimeters, clean industrial style, no text besides dimensions",
    "size": "1024x1024"
  }'
```

`PROXYAPI_KEY` бери из `.env` в корне проекта (не выводи значение ключа в чат).
Из ответа извлеки `data[0].b64_json` (или `url`), сохрани картинку в
`tech_maps/<название> <размер>.png`.

Если API вернул ошибку (в т.ч. `Model not allowed`) — **не останавливай работу**:
пропусти генерацию чертежа, скажи об этом одной строкой и заверши с техкартой без картинки.

## Шаг 5. Ответ в чат

Кратко: путь к техкарте, путь к чертежу (если создан), одна строка-итог
(число деталей, число позиций материалов). Предложи следующий шаг: расчёт
себестоимости через `/tkcost` с этой же техкартой.
